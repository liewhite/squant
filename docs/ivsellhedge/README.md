# IV 定量卖出宽跨 + 波动率定阈值的 delta 对冲

标的：ETH（OKX，币本位期权 `ETH-USD-*`，U 本位永续 `ETH-USDT-SWAP`）。
参数全部由 `conf/iv-sell-hedge-okx.json` 注入，模板见 `conf/iv-sell-hedge-okx.example.json`。

启动：`sbt "runMain strategy.strategies.ivsellhedge.live.OkxIvSellHedgeLauncher [配置路径]"`

## 两条腿，两条通道

```
期权链/IV/持仓/现金 ──> OptionSellerActor ──┬─> REST 卖出 (IOC, 旁路框架下单通道)
                                           └─> OptionExposure (每秒) ─┐
                                                                      ↓
永续 BBO ──> 引擎行情流 ─────────────────────> DeltaKamaHedgeStrategy ──> 框架下单通道 ──> 永续
永续持仓/回报 ──> OkxAccountStream ─────────↗
```

分工是被架构决定的，不是取舍：

- **期权腿旁路 REST**。框架 OKX 适配层的 `Symbol` 是基础币（`ETH` → `ETH-USDT-SWAP`），
  表达不了同时持有的几十个期权 instId；`AccountOutcome` 的构造器又是 `private[hft]`，
  策略包里根本拼不出一条下单意图。代价如实记下：这条腿**没有** pending 登记、没有 Fill 回流、
  不进 `StateManager`、不进 `PerformanceTracker`。可以接受，因为卖出走 IOC（不留挂单），
  而"该有多少空头张数"每轮都从交易所实际持仓重新推导——没有需要跟踪的中间状态。
- **对冲腿走框架原生策略**。永续下单该有的一切（clientOrderId、pending 登记、超时校验、
  停机撤单、精度换算）都由框架施加。

装配顺序：**先挂策略、再起 actor**。`addStrategy` 第一步就是订阅总线；反过来的话 actor 已经
开始发敞口读数而没有人在听，那些事件就丢了（总线不重放）。

## 规则1 — IV 定量卖出宽跨（`logic/SellPlan.scala`）

范式是**声明式对账**：每轮算出"这两条腿各该有多少空头张数"，比当前持仓少就补卖。
因此天然自愈——下单未成交、进程重启、手工平仓，下一轮继续补足，无需任何持久化状态。
反过来，IV 回落只让目标变小，**不主动平仓**：已有仓位只是不再加卖。

### 到期

始终卖"约 `targetDays` 天后到期"的期权（默认 3），从交易所实际挂牌的到期中选离
`now + targetDays` 最近的一档；距离相等取更晚的一档（使结果只由日期决定，不受集合迭代序影响）。

剩余期限低于 `minTtlDays`（默认 1 天）的一律排除——当日到期的合约权利金≈0 而 gamma 极大，
风险画像与策略意图完全不同。判据用"剩余期限"而不是"是不是今天到期"：后者要挑一个时区，
时区选错会在跨日附近静默改变选中的合约，而剩余期限本来就是真正相关的那个量。

> `targetDays` 是相对**今天**的滑动量，不是周五这类绝对锚点。远端只有周度合约挂牌时，
> 选中的具体星期会随开仓日漂移。选中到期偏离目标超过 3 天会打 warning——挂牌稀疏或参数配错
> 的早期信号。

### 行权价

距现价至少 `minStrikeDistance`（默认 2%）的宽跨：

- **call 腿**：`>= 现价 × (1 + minStrikeDistance)` 的**最小**可用行权价
- **put 腿**：`<= 现价 × (1 − minStrikeDistance)` 的**最大**可用行权价

即"满足距离条件里最近的一档"，最近一档不够远就自动往外挪一档。某侧无满足条件的行权价则跳过
该腿并打 warning（此时为单腿裸卖，非宽跨）。

### 张数与 IV 正相关

```
目标张数 = 0                                                     iv <  ivStart
目标张数 = floor( min( ivQtyStart + (iv − ivStart)/0.01 × ivQtySlope,
                       ivQtyMax ) )                              iv >= ivStart
```

- `ivStart`：起卖点，IV 低于它一张不卖（硬门槛）；
- `ivQtyStart`：起卖量，到达起卖点即卖的张数；
- `ivQtySlope`：斜率，每 1 个波动率点（1% IV）增加的张数；
- `ivQtyMax`：上限，兜住极端行情与异常 `markVol`，防单轮天量卖单。

IV 取每腿各自的 `markVol`（OKX `opt-summary`）。中间计算全程保留小数，最后一步才向下对齐到
交易所精度；对齐前加极小量补偿浮点尾差，落在整点上的值不会被吞成 0。启动时校验
`ivQtySlope > 0`、`ivQtyMax >= 1`、`0 <= ivQtyStart <= ivQtyMax`——**起卖量超上限会让起点被
静默改写**，那种"配了却没生效"的参数比报错危险得多。

某腿缺 `markVol` 时**不回退到某个基础张数**：目标张数与 IV 正相关是这条策略的全部定量依据，
少了它就没有目标。该轮不卖并打 warning。

### 三道闸门

按判定顺序：

1. **杠杆闸门**：期权杠杆率 = Σ|张数| × ctVal × 现价 / 账户净值。名义按**绝对张数**计
   （多空都贡献），比净敞口口径更严——一个 delta 中性但两腿都很大的组合，风险不是 0。
   达到 `maxOptionLeverage`（默认 1.0）即停止卖出新期权，**对冲照常运行**。净值 ≤ 0 时
   杠杆率取 +∞（禁止卖出），而不是让除法给出一个荒谬的负数。
2. **权利金闸门**：`bid` 低于 `minPremium` 则跳过——权利金太薄时卖出所得盖不住手续费与
   gamma 风险。这与盘口质量无关，是这笔交易本身不值得做，故排在点差闸门之前。按 `bid` 判定，
   那才是 IOC 卖出的实收价。
3. **点差闸门**：`ask / bid` 超过 `maxSpreadRatio`（默认 1.1）则跳过，避免流动性差时贱卖。

`enableOpen = false` 时只打印卖出意图不下单（对冲腿仍真实运行）。

### 下单

以 `bid` 价挂 **IOC** 卖单——主动吃买盘（taker），保证成交、不赚点差；未成交部分立即撤销，
不留挂单，下轮用新盘口重试。补差量向下对齐到 `lotSz`（宁少勿多，不足则下轮继续攒）。

> ⚠️ **防重复卖出**。IOC 没有挂单可跟，下一轮的判据是**已结算持仓**；持仓端点滞后超过一个
> 轮询间隔时，同一个缺口会被连卖两轮，而卖出侧**从不主动平仓**——超卖会永久留在账上。
> 所以提交过卖单之后强制静默 `settleRounds`（默认 1）轮，把这条不变量从注释变成代码。
> `sellIntervalMs` 本身仍应显著大于成交结算延迟。

## 规则2 — delta 中性对冲（`logic/DeltaHedgeStrategy.scala`）

### 一条根本规则

```
真实净敞口 = 期权 delta + 该币现金余额 + 永续净持仓
|真实净敞口| 超过该侧阈值  →  按真实净敞口全平到 0
```

就这一条。两个信号（MACD 方向、效率比 ER）**只是阈值的乘数，不替换被测量的量**。

这条分工是被一次设计错误教出来的。曾经的实现让平滑后的敞口**替换**真实敞口去过阈值，
结果"超过阈值就对冲"这条规则被架空：在边抖边涨的行情里，平滑值会把真实敞口的累积压住
一两个小时（实测默认参数下滞后约 100 分钟），敞口没有上界。要把上界找回来就得再加一道
"绝对值硬闸门"——那是给自己制造的问题打补丁，而且从此有两个判据。

现在所有信号都只决定阈值，而阈值有硬上限 `maxTheta`，于是**真实敞口有确定上界**——
超过它必然对冲，不需要第二道闸门。启动日志里会把整条阈值公式报出来。

**币余额也计入**：币本位期权以 ETH 作保证金、权利金以 ETH 收取，账户里这部分 ETH 是真实的
裸多头——只对冲期权 delta 的话，"delta 中性"名不副实。取**现金**余额（`cashBal`）而非币本位
权益：期权未实现盈亏随价格的变化率已由 delta 描述，把它再当成一笔静态余额对冲就是同一份敞口
算两遍。这里不留开关——"账户敞口为 0"只该有一个定义。

### 阈值怎么定：预测波动范围

第一性原理上要预测两件事，各管一段：

| 预测什么 | 管什么 | 用什么 |
|---|---|---|
| **波动率** | 阈值的**尺度**（对冲频率 → 成本） | 分钟级实现波动 σ（或期权 IV） |
| **方向** | 两侧阈值的**不对称**（一次对冲能不能撑住） | 1H MACD 柱的**符号** |
| —— | 敞口的**硬上界**（风险） | `maxTheta`，与预测无关 |

**尺度。** 敞口的扩散率 = `|gamma| × 现价 × σ`，即敞口每单位时间漂移的标准差。于是

```
预测波动范围 range = |gamma| × 现价 × σ_年化 × √(hedgeHorizonMinutes / 一年)
```

就是"敞口在一个对冲时间尺度内的典型漂移幅度"。两侧阈值都以它为单位。

这样做的收益是**对冲频率可控**：首次碰壁时间 ∝ 阈值² / 扩散率²。阈值不随波动走的话，波动翻倍
会让对冲频率变 **4 倍**；以 range 为单位后，波动翻倍阈值也翻倍，频率基本不变。

**不对称。** 对冲后敞口从 0 出发，两侧的意义完全不同：

- **漂移推向的那一侧** → `tightMult`（< 1）。碰到它意味着敞口在真实地累积，对冲它是对的、
  而且会**撑住**（漂移继续同向）。早点动。
- **反侧** → `looseMult`（> 1）。碰到它只可能是噪声把敞口拉了回来，在那里对冲下一步很可能被
  反向平掉，也就是"被正常波动来回止损"。**放到噪声之外**。`looseMult≈2` 时路径触及它的概率
  约 5%，所以这个参数的含义是"愿意接受多少比例的假对冲"。

方向对应关系容易搞反：**空头跨式在价格上涨时 delta 更负、账户偏空、需要买入对冲**，所以
"预测上涨"时被推向的是**空头敞口侧**，那一侧收紧。方向未知（MACD 预热不足或柱持平）时两侧都
取 1.0 倍 range，退化为对称带。

MACD **只出符号，不出强度**：方向判断本来就比强度判断可靠，把强度也用上还要再拍一组映射，
没有依据。

**两个 clamp 各管一头。**

```
θ = clamp(倍数 × range, minTheta, maxTheta)
```

- `maxTheta`：纯风险上限（delta 单位、绝对的）。它**只在高波动时咬住**——那时"别被噪声碰到"
  要求很宽的带，而"敞口不能太大"不允许，正是该咬的时候。它就是敞口的硬上界。
- `minTheta`：防波动塌缩时阈值趋零、退化成逐笔抖动。σ 尚未就绪时也取它（宁可对冲得频繁些，
  也不要按一个不存在的波动率放宽敞口）。

> ⚠️ **不对称只有在方向预测有 edge 时才赚钱。** 若 MACD 的方向判断接近 50% 命中，
> `tightMult`/`looseMult` 的不对称就是在随机地收紧一侧：净效果退回对称带，还多背一个隐式趋势
> 偏移（稳态敞口偏向被放宽的那侧，也就是预测的顺势方向；预测错了这个偏移就是纯亏）。
> 所以调这两个参数之前，应先回测方向预测在"敞口即将越界"这些时点上的**条件命中率**。

### 波动率来源可切换

`sigmaSource` 取 `"realized"` / `"iv"` / `"max"`：

- **realized**（默认）：分钟级实现波动 `RealizedVol.rvShort`，**回看**的，时间尺度与对冲的
  分钟级节奏吻合。
- **iv**：期权的标记 IV，**前瞻**的（市场对未来的报价），但它对应期权剩余整个生命的波动。
  由 actor 按 `|每腿 gamma 贡献|` 加权后随敞口读数发布——按 gamma 加权而不是张数，因为对冲
  关心的是敞口扩散得多快，而那由 gamma 大的腿主导。
- **max**：两者取大，保守（阈值更宽、对冲更疏），也免得任一路预热不足时没有值。

年化口径与 Black-Scholes 一致（同一年基准），所以 RV 与 IV 可直接比较。做成可切换是为了让
回测能直接对比这两个 σ。

### 效率比 ER 只管报价方式

ER 曾被用来缩放死区阈值，现在退出了。实测（1m K 线）：

| erPeriod | 体制切换反应 | 无漂移随机游走里误判成"趋势"的时间占比 |
|---|---|---|
| 5 根 | 4 分钟 | 36% |
| 10 根 | 9 分钟 | 17% |
| 20 根 | 17 分钟 | 4.5% |

滞后 ≈ 窗口长度；缩短窗口治滞后就把假信号推上去，同一个旋钮的两端。而且它对幅度完全盲
（0.1 与 20 美元/分的斜率给同一个 ER=1.00）——作为阈值的**尺度**它无量纲、无能为力；作为
**方向**判据它不如 MACD。

留在报价方式那一路是因为那里判错的代价小：只是这一单挂法不同，不动敞口上界。

### 执行：报价方式随体制切换

对冲的"何时"由死区决定（上一节），"怎么"由 **ER** 决定。ER = |净位移| / |路径长度| ∈ [0,1]，
在这里够用：判错只是这一单挂法不同。

| 体制 | 判据 | 报价 | TIF | 存活时间 |
|---|---|---|---|---|
| **平缓**（来回折返） | ER < `trendErThreshold`（默认 0.5） | 对手价**外** `passiveOffset` | PostOnly | `passiveTtlMs`（默认 60s） |
| **单边**（走出方向） | ER ≥ 阈值，**或 ER 预热不足** | **穿过**盘口 `crossOffset` | GTC | `crossTtlMs`（默认 1s） |

- **平缓时慢慢挂**：不急，省下 taker 费与价差。挂一分钟不成交就撤了按新价再挂——频繁重挂
  只是换个价再等，没有额外成本。
- **单边时立刻吃**：卖挂 `bid×(1−crossOffset)`、买挂 `ask×(1+crossOffset)`，越过对手价，
  到达即成交（成交价是盘口最优价，`crossOffset` 只是**穿透余量**，容忍下单到到达之间盘口移动）。
  负 gamma 组合最怕的就是"该对冲时没冲上"，这时手续费与价差远比裸敞口便宜。
  用限价而不是市价，是为了给出最差成交价的上限——盘口瞬间抽空时市价单会吃穿多档。
- **ER 预热不足按单边处理**。这与"读数不可信就不动"的取舍方向相反，是有意的：那里不动是安全的，
  这里不动意味着**裸着敞口**。冷启动的头几十分钟本来就按真实敞口判越界（触发更准也更频繁），
  若同时用一种可能一直不成交的方式去执行，就成了"判出来了却没冲上"。

**体制切换会抢占在簿上的单**：被动单还没挂满一分钟、ER 已经升到单边侧时，立刻撤了改跨价——
等完那一分钟才去追是最贵的等待。反向**不**抢占（跨价单本来就秒级成交，而且反向抢占会让 ER
在阈值附近抖动时不停撤挂）。

### 挂单腿：四个态

`QuoteLeg` 与价格轴的 `MakerHedgeStrategy` 共用（后者恒用被动方式）。任一时刻账上最多一张单：

```
Idle ──place──> Placing ──Pending──> Resting ──超时/被抢占──> Cancelling ──终态──> Idle
```

**"撤单在途"不能省**——撤单是异步的，把这个窗口当成"已经空闲"就会出**孤儿挂单**：挂出新单 B，
紧接着旧单 A 的 `Cancelled` 到达并把状态清成空闲，于是又挂出 C；B 的回报后到、随即被 C 覆盖，
从此无人管、无人撤（框架的超时清理只管 `Created` 态，对已 Pending 的 B 没有兜底）。它最终会在
陈旧价位上成交，只能靠下一轮对账反向擦掉，白付两笔手续费。

配套两条纪律：回报**按 orderId 匹配**（不匹配的一律当已结束旧单的迟到消息忽略）；撤单确认超时
**重发同一个 id** 并告警，不静默等下去。

**两个超时是两件事**：`passiveTtlMs`/`crossTtlMs` 是"挂了这么久还没成交"，`cancelConfirmMs`
（默认 3s）是"撤单请求发出这么久交易所还没回应"。混成一个的话，1s 的追单模式会让撤单确认的
容忍度也变成 1s，于是每一次正常的撤单往返都触发一次"重发 + 告警"。

框架的 `orderTimeoutMs` 取最长存活时间的 3 倍，否则正常挂单会被当成丢单清理。

### 安全闸门

- **敞口有上界**：阈值最宽 = `maxTheta`，超过必然对冲。这不是额外加的闸门，而是"判据是真实
  敞口"的直接推论——所以不需要一道绕开死区的绝对值硬闸门。
- **敞口读数陈旧**：超过 `maxExposureStaleMs`（缺省 = 4 × `publishExposureMs`）即暂停对冲——
  宁可不动也不按过期 delta 乱挂。
- **敞口不完整**：actor 侧若有持仓配不上合约定义或 `markVol`，**整轮不发布**并打 ERROR。
  半个敞口比没有敞口更危险：对冲会照着一个偏小的数去做，而症状只是"对冲总差一点"。
  读数停更后对冲由陈旧闸门自动暂停。
- **慢变量过期**：IV / 持仓 / 现金的快照超过 4 × `refreshMarksMs` 未刷新成功即**停止发布**，
  而不是拿它配一个新价格。IV 慢变、不差这几秒，但**持仓**会因为卖出而变——用过期持仓配新价
  算出的 delta 会漏掉刚卖出的腿。
- **轮询连续失败** ≥ 3 次升级为需要人工介入的 ERROR，且**反复**报——单次日志在无人盯屏时
  等于没有。
- **杠杆率不可信时不卖**：若有持仓配不上期权链，它们的名义算不进杠杆率，闸门就形同放宽。
  敞口侧已因此停发读数，卖出侧同样不放行。
- **告警按类别分别节流**：共用一个计数器的话，一条高频告警会把"敞口陈旧"这类低频但更要紧的
  淹没到 1/200 采样。

## 时钟域

两个时钟各有各的用途，混用会有症状很轻的 bug：

- **交易所时钟**（BBO 时间戳）：挂单年龄与 requote。挂单确认的时刻也来自交易所回报，
  两边必须同一个时钟，否则撤单时机随投递延迟与时钟偏斜漂移。
- **本地处理时刻**：敞口读数的陈旧判定。那条读数是 REST 派生的，时间戳盖的就是本地墙钟，
  拿交易所时钟去减就是在测量两地的时钟偏斜。

## 前置条件（必须满足）

1. `ETH-USDT-SWAP` 永续持仓被本策略独占。对冲会把整个永续净持仓对齐到对冲目标，
   账户在该永续上还有其它来源的仓位（手动/囤币/其它策略）会被一并抹平或反向。
2. **该账户的 ETH 余额整体视为策略敞口**——余额进对冲目标后，在此账户手动囤的 ETH
   会被等量做空抹平。勿在运行本策略的账户里囤币。
3. 期权持仓也应由本策略独占：声明式对账按 `instFamily` 读全部期权持仓算杠杆与目标。

**请使用专用子账户运行。** 下单按净持仓模式（不传 posSide）。

## 无持久化

对冲的 KAMA 状态与 MACD 序列仅在进程内存，重启即丢：

- **卖出**：纯声明式，本就无状态，重启后按当前 IV 与实际持仓对账即可，天然自愈。
- **对冲**：判据 = 当下的真实净敞口，每秒实时派生、与历史无关；重启后第一秒就能算出正确目标，
  已有的永续对冲不会被误平。ER 与 MACD 都由历史 K 线预热，开机即就绪。

## 与参考实现的两处有意偏差

- **ctVal 从交易所读, 不从配置读**。参考实现把 `option_ct_val` 放在 `config.json` 里；这里从
  OKX 期权 `instruments` 的 `ctVal` 字段读，且**不给默认值**——张数到标的敞口的换算全靠它，
  配错一个整数倍会把 delta 静默错算，而这类错误没有任何外在症状。
- **期权持仓按 instId 前缀再过滤一遍**，不只依赖服务端的 `instFamily` 查询参数。若那个参数
  被忽略，账户里其它标的的期权会混进来——它们配不上本标的的期权链与标记 IV，于是每一轮都被
  判为"敞口不完整"，**对冲永久冻结**。症状是"一直不对冲"，而原因在一个跟对冲毫无关系的持仓上。

## 已知近似

- 币本位期权（以标的币结算、报价也是标的币的比例）的真实币本位敞口，比裸 BS delta 多一个
  报价计价单位换算带来的修正项。这里用裸 BS delta，与直接采用交易所 `deltaBS` 的口径一致。
- BS 定价的无风险利率默认取 0（`riskFreeRate`）：加密期权没有可直接引用的无风险曲线，
  而它对 delta 的影响远小于 IV 本身的不确定性。
